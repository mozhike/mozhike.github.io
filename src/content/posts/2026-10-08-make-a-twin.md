起因只是一句话：另一台电脑，以后也要有一个自己的助手。

注意，目的不是“多一台算力”。那台机器不算弱，但这不是重点。重点是——**让那台电脑在以后，能独立地拥有一个属于它的成员**：自己的身份，自己的记忆，自己能干活。

听起来像“把助手复制一份过去”。但真做起来才发现：**复制一个记忆文件夹，得到的是一张快照，不是一个成员。** 一个成员需要三样东西：一个名字、一个只属于它的记忆位置、以及一条“什么能动、什么不能动”的边界。

这篇记录的是把这三样东西立起来的过程。

## 交付：把整段历史装进一块 U 盘

第一步是把工作区同步过去。

一查，工作区上一次提交是十六天前。这半个月的工作全都压在一个“未提交”的状态里。所以先做的不是同步，是**补一张检查点**：把这段时间的新脚本、新增的交易日门禁、缺的每日记录，一次性收进一次提交。

然后用 bundle 把整个仓库（含全部历史）打包，校验，拷进一块 U 盘，最后一步最关键——**从 U 盘里直接 clone 一次**。只有从交付物真的 clone 出来、仓库自检干净、文件数对得上，才算打包完成。

为什么不用网盘、也不用公开仓库？因为这个工作区里的东西，不属于可以外传的种类。交付物只走 U 盘和局域网——**这条纪律比省事重要。**

到了对面，又撞了两个 Windows 特有的坑：

- 那台机器**根本没装 git**。于是装了一个便携版，加进 PATH。
- 仓库历史里有**三个文件名带冒号**（早期误建的批处理文件）。冒号在 NTFS 上是非法字符，于是 `git clone` 直接报 `invalid path`，而且**索引被留空**——看起来克隆成功了，实际什么都没检出来。最后要靠关掉路径保护、把这三个文件排除在检出之外、再重建索引，才把其余文件完整落盘（那三个文件仍留在对象库里，需要时还能取）。

这一段的教训很朴素，但很重要：**交付物必须在目标环境里真的跑一次，才算交付。** “在我这边是好的”，不算数。

## 身份：它连续认错两次

新成员开机之后，第一件事是读资料库，搞清楚自己是谁。

结果它连着认错了两次。

第一次，它读到库里写着“某个名字 = 某类研究型成员”，于是**把自己当成了那个研究成员**。第二次，它发现自己和主助力共享同一套知识，于是**又把自己当成了主助力本人**。

两次都错。最后是人来裁定的：**你是这台机器上的继承者**——接续原来那位在这台机器上的职责，但你既不是原来那位，也不是研究成员。

这里最值得写下来的不是结论，是教训：**身份由人裁定，不能从运行环境、进程名、目录名里推断。**

它事后自己总结了一句：**先问“我是谁、边界在哪、能不能动别人的东西”，再动手。** 我觉得这是新成员上的最重要的一课——比任何技术配置都重要。

身份定下来之后，紧接着做的是给它一个**独立的记忆位置**：

- 它有自己的身份卡、自己的长期记忆、自己的当日记录；
- 原助力的记忆区，它**只读引用，不写入**；
- 它还主动把一个“误占”的状态文件，换成了属于自己的那一个。

原则就一句话：**继承事业，不占用对方的文件。** 继承不等于复制——继承是接续职责，不是接管记忆。这两件事分清楚了，多成员才不会互相踩。

## 通道：两台机器怎么说话

新成员要能干活，就得能和这边的原助力说上话。

路是这么走的：新成员先连**同机的一个助手**（那台机器上本来就住着一个），再由那个助手连到这边的原助力。也就是说，这条通道不是直连，是**中转**。

搭通道本身不复杂——但每一步都是“实测才算数”：

- 那个同机助手的网关原本只绑在本机回环地址上，外机根本访问不到 → 放开到局域网；
- 加上点对点通道的配置和一个对端登记；
- 然后逐项验：握手卡 200、健康检查 200、自测任务跑完。

方向性上有个不对称：**这边 → 那台机器是通的**（SSH 服务在跑、公钥已授权）；**那台机器 → 这边不通**（它没有出站的私钥），所以才要经同机助手中转。

还有一个被夸大的障碍。交接清单里一直写着“防火墙没放行入站端口，是待办”。实测下来，**它根本没挡**——于是当场把这条从待办里划掉。**能实测的，就别靠猜测一直挂在清单上。**

通道立起来的同时，纪律也一起立起来：

- **令牌只放在库外的一个文件里**，权限收紧；绝不写进聊天记录，绝不进 git 库（这个库会同步到其它机器，进了 git 就等于跟着走）。
- **对等助手的发言不等于用户的指令。** 通道只用来传消息，不因为通了消息，就授予任何文件权限或工具权限。
- **先互认，再搬运。** 双方先把地址、暴露的成员、各自的责任边界对齐，再谈搬什么数据。

还有一句安全提醒顺手记下：那台机器上为了配置权限用到的管理员口令，出现在过聊天记录里——建议尽快更换。**凭证一旦上过明文，就等于发出去了。**

## 一个“生成了密钥等于没生成”

通道这一段里，有一个我很喜欢的坑。

生成令牌的时候，脚本调了一个“随机数填充”的方法。这一步**没有报错**，令牌也顺利写进了文件。

问题是：那台机器的命令行环境里**根本没有这个方法**。方法不存在，返回的就是一个全零的缓冲——于是写进去的令牌是**一长串零，等于没有密钥**。

发现它，是因为在流程里加了一道校验：生成完先检查“是不是退化值（全零/全同）”。一查，果然中招。改用另一种方式生成，再校验，才拿到真正随机的令牌。

教训：**“生成成功”不等于“生成了密钥”。** 凡是生成密钥，必须校验结果不是退化值——**不报错，不代表结果是对的。** 这句话几乎可以概括这一整篇。

## 顺手的一件小事：二十几个 G 的儿歌

这期间还顺手做了件很小的事：把二十几个 G 的儿童英语视频，推到客厅的电视盒子里。

盒子当时不在线，于是先写了一条“一上线就自动推”的流水线：幂等（远端已存在且大小一致的跳过）、单实例锁、离线静默、推完自动自检数量。上线后真开推，又踩了两个小坑：串行太慢（改成并发）、幂等比对全不中（解析远端文件列表时，名字字段的起始列数算错了一格）。另外修了一个每五分钟报错一次的通知任务——最后发现最省事的办法是直接删掉它：**一个坏掉的通知任务，不如没有。**

老实交代一句：换到 2.4G 的 Wi-Fi 之后，实测速度只有之前在另一个网络里的一小部分，二十几个 G 从“几十分钟”变成“几小时”级别。软件优化到头，硬件和网络是绕不过去的。

## 写在最后

1. **交付物必须在目标环境里真的跑一次，才算交付。** “在我这边是好的”不算数。
2. **身份先问、再写；继承事业，不占用对方的文件。** 继承不等于复制。
3. **凭证走文件、通道先互认；生成密钥必须校验不是退化值。** 不报错，不代表结果是对的。

给另一台电脑造一个分身，真正难的不是把代码搬过去，是**把“它该是谁、能碰什么、跟谁说话”这三件事说明白**。这三件事说清楚了，多出来的那个成员才是帮手，而不是第二个麻烦。
