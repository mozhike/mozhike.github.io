## 一句话

一套跑在自己电脑上的 A 股监测系统：每天自动抓数据、算形态与因子、生成观察名单、推送到手机，第二天自己回来对答案。

它不接券商、不下单，也不预测明天涨跌；它只做一件事——把「每天固定要做、但人做不完也做不准」的动作固化下来。

## 为什么做

三个很现实的问题：

- 五千多只股票，一个人盯不过来；
- 看盘软件的预警规则是死的，券商条件单写不出复杂逻辑；
- 大部分选股工具是黑盒，只给名单，不给理由。

目标也就三句话：**能自跑、能验证、能解释**。

## 原理：五层闭环

系统是按「五官」长出来的，不是按功能清单堆出来的：

| 层 | 干什么 | 关键设计 |
|---|---|---|
| 👁 眼 · 数据 | 全市场日线、分钟线、实时快照 | 本地库 + 实时接口双源互备；交易日、复权、代码格式统一成一层「地基」 |
| 👂 耳 · 信息 | 新闻、热榜、外围期货、地缘事件 | 自动存档，供交叉验证，不直接进决策 |
| 🧠 脑 · 分析 | 形态识别、因子打分、板块与市场状态判断 | 规则与因子并行，任何结论都要能说清依据 |
| 👄 口 · 输出 | 盘前、午间、收盘后推送 | 只留固定几条，其余全部静默存档 |
| 🔄 反思 · 验证 | 次日对答案、周度复验、区间复盘 | 每条预测入库，错了也留档 |

一句话概括：**没有反思层的系统，只是一个会说话的筛子。**

## 选股逻辑：三段生命周期

把一只股票的底部反转拆成三段看：

| 阶段 | 长什么样 | 系统的态度 |
|---|---|---|
| 磨底 | 缩量、贴着均线、慢慢阴跌 | 重点观察池，等信号 |
| 临界 | 形态将破未破、量能开始变化 | 用因子排序，谨慎盯 |
| 启动 | 已经放量拉起 | 回避清单，提防追高 |

这里必须写清楚一个认知：**技术形态是必要条件，不是充分条件**。事后看，每只大涨的股票都长这样；事前看，大多数长这样的股票会继续阴跌。所以第一段只做观察池，不做预测承诺。

系统里同时跑两套选股：

- **规则版**：硬条件筛形态，可解释、稳定，但覆盖偏窄；
- **因子版**：把形态变成 0~1 的形状参数，加权求和排序，覆盖广，但容易过拟合。

两版**并行跑、互相印证**，选股结果都只存档不推送，定期裁决谁上岗。新因子也不能直接进生产：先准入，再进观察期，再用近端滚动样本做样本外验证，最后人拍板。

## 一天在做什么

- **盘前**：更新行情缓存，生成早报——隔夜外盘、盘前要闻、热榜、观察池昨收。
- **盘中**：定时扫描全市场，触发式评估急涨急跌、回撤、涨停/炸板；午间出简报并保存快照。
- **收盘后**：补齐日线，跑选股与板块分析，验证昨天的预测，发收盘晚报。
- **周末**：因子 IC 复验与权重更新、规则版与因子版回测、周度复盘。

一个反直觉的纪律：**大部分产出不推送**。名单、评分、验证报告默认只入库，因为每天十几条消息只会让人把系统静音。推送只保留固定几条，加上真正需要人看的异常。

## 设想与达成情况

写系统介绍最容易变成自我表扬，所以这张表按「最早怎么想的 / 现在什么样 / 算不算做到」来填：

| 最早的设想 | 现在的状态 | 判定 |
|---|---|---|
| 全自动无人值守 | 没有人工介入也能每天跑完；但机器休眠或断电仍会造成缺口，靠断档检测和缺失登记兜底 | ✅ 达成，但不完美 |
| 每个判断都能验证 | 预测全部入库，次日自动对答案，周末复验；补不回来的数据登记为「永久缺失」，不补、不造 | ✅ 达成 |
| 规则版换成因子版 | 两版并行验证后，因子版被降级观察，关键阈值也没有为了名单好看而放宽 | 🟡 部分达成（未替换） |
| 从定时跑改成事件触发 | 盘中触发评估、断档检查、补跑守护已上线；核心流程仍以定时驱动为主 | 🟡 部分达成 |
| 开放标准 API | 本地 REST API 已跑通，任务与管线可以程序化调用；对外接口尚未开放 | 🟡 部分达成 |
| 数据维度继续加深 | 资金流、财务指标已入库并参与筛选；更多维度还在排队 | 🟡 部分达成 |
| 三段生命周期识别 | 已上线，但只用于观察和排序，不作为交易信号 | ✅ 达成（观察期） |
| 系统要能解释自己 | 文档自动检查、状态镜、缺失登记、变更记录 | ✅ 达成 |

## 现在还不行的地方

- **解释力有限**：现有因子大约只能解释一成左右的横截面差异，离真正的「模型」还很远。
- **有明显偏好**：对高活跃、有资金关注的股票更准；对银行、地产这类低波动品种基本失效。
- **形态不等于结果**：磨底形态是必要非充分条件，真正的驱动往往来自消息、板块和资金，系统看不到全部。
- **数据完整性是最大单点**：过去几次事故都出在这一层——不是策略错，是数据错了却没人发现。
- **不碰交易**：不下单、不接券商、不给仓位建议，所有输出都只是「值得看一眼」。

## 怎么维护

代码、文档、变更记录三件事一起做：先改代码，再改文档，最后记一笔。文档有自动一致性检查，数据缺失有登记表，预测有对账表。

日常由一个「运维型」和一个「开发型」AI 助手分担，我负责拍板：基准怎么定、异常要不要紧、哪个版本上岗。**AI 给速度，人给方向。**
